# Neovim configuration

LazyVim is the base. This directory contains local overrides and plugins. The
active config lives at `~/.config/nvim`; chezmoi stores its source at
`~/.local/share/chezmoi/dot_config/nvim`.

## Where to look

| Path | Owns |
| --- | --- |
| `init.lua` | entry point |
| `lua/config/lazy.lua` | lazy.nvim bootstrap and LazyVim import |
| `lazyvim.json` | enabled LazyVim extras |
| `lua/config/options.lua` | globals and editor options set before plugin startup |
| `lua/config/keymaps.lua` | editor-wide keymaps loaded on `VeryLazy` |
| `lua/config/autocmds.lua` | editor-wide autocmds loaded on `VeryLazy` |
| `lua/plugins/*.lua` | one feature or plugin override per file |
| `autoload/db/adapter/` | Dadbod's DuckDB compatibility adapter |
| `lazy-lock.json` | resolved plugin commits, generated by lazy.nvim |

The plugin files are flat because lazy.nvim imports the Lua files directly
under `lua/plugins/`. Keep plugin-specific mappings, commands, and load triggers
with the spec that owns them.

## Plugin map

| Area | Files |
| --- | --- |
| appearance and navigation | `colorscheme.lua`, `smear_cursor.lua`, `snacks.lua`, `vim-tmux.lua` |
| AI | `claudecode.lua`, `copilot.lua`, `copilot-lsp.lua`, `opencode.lua` |
| languages and tooling | `clangd.lua`, `flutter.lua`, `treesitter.lua`, `vtsls.lua`, `markdown.lua`, `sniprun.lua` |
| data and remote work | `dadbod.lua`, `remote-nvim.lua` |
| media | `img-clip.lua` |

LazyVim extras cover other languages, including Elixir and SQL. Check
`lazyvim.json` before adding a plugin spec for something LazyVim already owns.
As of 2026-09-22, the live config has `markdown.lua` and `sniprun.lua` while
chezmoi has `bufferline.lua` and `obsidian.lua`. The TypeScript extra and server
settings also differ. These are existing choices, so review `chezmoi diff`
before a broad apply.

## Change or extend it

1. Check whether the feature is already a LazyVim extra in `lazyvim.json`.
2. For a new plugin, add one file under `lua/plugins/` returning a lazy.nvim
   spec. Add its `keys`, `cmd`, `ft`, or `event` in that file.
3. For an existing plugin, edit its file. Avoid a second spec unless LazyVim's
   merge behavior is needed.
4. Mirror intentional changes to the chezmoi source. Inspect with
   `chezmoi diff -- ~/.config/nvim` before applying anything broadly.

The theme spans three settings: `background = "light"` in `options.lua`, the
Catppuccin Latte options in `colorscheme.lua`, and LazyVim's startup
colorscheme in `lazy.lua`. Keep those aligned when changing themes.

`treesitter.lua` owns the Treesitter branch, load event, parsers, and text
objects. `dadbod.lua` owns the `masters` DuckDB connection; its adapter handles
DuckDB 1.5 table discovery. SQL query usage and recovery steps are in the
Obsidian note `Reference/neovim-sql-dadbod-duckdb.md` in `my-void`.

## Quick checks

```bash
~/.local/share/nvim/mason/bin/stylua --check lua
nvim -n -i NONE --headless '+lua print(require("lazy").stats().count)' +qa
chezmoi diff -- ~/.config/nvim
```

For mapping problems, inspect the owner with `:verbose nmap <keys>`. For plugin
load problems, use `:Lazy` and `:messages`.
